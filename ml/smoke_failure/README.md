# Прогноз неисправности дымовых датчиков

CatBoost прогнозирует начало зарегистрированного состояния `Неисправен` в ближайшие 24 часа. Используются архивы **только за 2022–2023 годы**, каналы типа `Датчик дыма`. Это производная метка по журналу, не подтверждённый физический отказ.

## Расширенное исследование 2019–2026

Для всех восьми годовых архивов с теми же правилами разметки и признаками:

```powershell
.\.venv\Scripts\python.exe -X utf8 ml/smoke_failure/full_study.py
```

Обучение: 2019–2023. Валидация: 2024. Тест: 2025 и первое полугодие 2026. Результаты сохраняются отдельно в `output/smoke_failure_2019_2026`: модель, отчёт, метрики, годовая статистика, концентрация положительных примеров по каналам, графики и проверочные прогнозы. Годовые архивы объединяются до расчёта истории, чтобы учитывать переходы через Новый год. `--rebuild` повторяет расчёт признаков и меток.

Прогноз расширенной моделью:

```powershell
.\.venv\Scripts\python.exe -X utf8 ml/smoke_failure/predict.py --model-dir output/smoke_failure_2019_2026 --events output/smoke_failure_2019_2026/events.parquet --as-of 2026-06-15T12:00:00 --output output/smoke_failure_2019_2026/risk_scores.csv
```

Ниже описан исходный эксперимент 2022–2023; правила наблюдаемости и формирования признаков общие для обоих исследований.

## Запуск

Из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r ml/smoke_failure/requirements.txt
.\.venv\Scripts\python.exe -X utf8 ml/smoke_failure/train.py
```

Для чтения архивов нужен 7-Zip: `7z` или `7zz` в PATH, стандартная установка Windows или путь в переменной `SEVEN_ZIP`. Архивы читаются потоком, целиком распаковывать их на диск не нужно. Результаты сохраняются в `output/smoke_failure`. Подготовленные данные используются повторно, если исходники и код обработки не изменились. `--rebuild` повторяет построение признаков и меток.

Прогноз на конкретный момент по подготовленной истории:

```powershell
.\.venv\Scripts\python.exe -X utf8 ml/smoke_failure/predict.py --as-of 2023-08-09T06:00:00
```

Своя выгрузка событий в исходном CSV-формате:

```powershell
.\.venv\Scripts\python.exe -X utf8 ml/smoke_failure/predict.py --events path/to/events.csv --as-of 2023-08-09T06:00:00 --output output/smoke_failure/risk_scores.csv
```

Также поддерживается Parquet со столбцами `channel_id`, `timestamp`, `state`, `alarm`. Идентификаторы фильтруются по справочнику; для обновлённого справочника есть `--dictionary`. Время используется в том же локальном формате без часового пояса, что и в журнале. Все события после указанного момента исключаются до расчёта признаков.

Результат содержит оценку `risk_score` и `warning`, определённый зафиксированным на валидации порогом. Оценка риска отдельно не калибровалась как вероятность. Для датчиков с текущей неисправностью (`already_faulty`), неизвестным состоянием (`unknown_state`), последним сообщением старше суток (`stale_observation`) или историей короче суток (`insufficient_history`) оценка остаётся пустой. Это не означает отсутствие риска.

## Разметка

1. Полные смысловые дубли удаляются. Противоречащие состояния одного канала в одно время становятся `AMBIGUOUS`; произвольный порядок по ID события не используется.
2. `Норма`, `Дыма нет`, `Обнаружен дым` считаются известными состояниями без зарегистрированной неисправности. `Неисправен` означает зарегистрированную неисправность. Другие состояния считаются неизвестными.
3. Переход из известного состояния без неисправности в `Неисправен` считается началом эпизода, если интервал между сообщениями не превышает 24 часа. Первый в истории `Неисправен` и повторные сообщения об одной неисправности не становятся новыми эпизодами.
4. Раз в час формируется пример, если история не короче 24 часов, последнее сообщение не старше 24 часов и текущее состояние без неисправности.
5. **Для обоих классов требуется наблюдение всего будущего окна 24 часа** без неизвестных состояний и промежутков между наблюдениями свыше 24 часов. Это дополнение исключает асимметричную разметку коротких положительных и длинных отрицательных окон.
6. `sensor_fault_onset_24h=1`, если в `(t, t+24ч]` начинается эпизод; иначе `0`. При неполном окне метка неизвестна, пример исключается.

Периодичность журнала не подтверждена. Порог разрыва в 24 часа является зафиксированным исследовательским допущением; отсутствие коротких незарегистрированных сбоев он не гарантирует. Ограничение применяется одинаково ко всем временным выборкам и выбрано до оценки модели.

## Обучение и проверка

- Обучение: 2022 год.
- Подбор числа деревьев и порога: январь–июнь 2023 года.
- Окончательный тест: июль–декабрь 2023 года.
- Перед границами периодов исключаются 24 часа, чтобы целевые окна не пересекались.
- Признаки используют события только с временем `<= t`. ID канала, будущая неисправность и метка в модель не передаются.
- Порог максимизирует Recall при Precision > 0,7 на валидации. Если такой порог недоступен, выбирается максимальный F1 на валидации.
- Для предупреждений дополнительно считается качество по эпизодам с паузой 24 часа между предупреждениями одного канала.

Тест предназначен для переноса во времени на существующий парк. Одни и те же каналы могут встречаться в обучении и тесте. Проверка на полностью новых каналах отдельно не проводилась. Часовые строки коррелируют: количество независимых эпизодов следует смотреть в отчёте.

Горизонт «в следующие 24 часа» допускает предупреждение за несколько минут до события. Он не гарантирует упреждение минимум на сутки. Для этого нужно переопределить целевое окно.

## Результаты

- `catboost_smoke_failure.cbm`: обученная модель.
- `model_metadata.json`: признаки, порог, настройки, версии и контрольная сумма модели.
- `report.md`, `metrics.json`, `evaluation.png`: результаты и ограничения проверки.
- `training_dataset.parquet`: признаки, метки, временные выборки.
- `test_predictions.parquet`, `test_alerts.csv`: проверочные прогнозы и предупреждения.
- `extraction_audit.json`, `dataset_audit.json`, `fault_episodes.csv`: источники и аудит разметки.
- `events.parquet`, `smoke_channels.csv`: отфильтрованные события и справочник.

При строгой обработке пробелов в этом наборе осталось **1210 размеченных часовых точек**. На окончательном тесте только **73 точки и один эпизод**. Полученные Precision=1,00 и Recall=0,857 нельзя считать доказательством эксплуатационного качества. Простое правило по прошлым неисправностям на этой маленькой выборке оказалось не хуже CatBoost.
