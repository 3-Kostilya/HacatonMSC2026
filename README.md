# Мониторинг инженерной инфраструктуры

В `main` находятся веб-интерфейс, API и только компоненты ML, необходимые
для запуска. Сервис принимает журнал событий (`.csv` или `.7z`) и два
справочника, сохраняет обработанные события в Parquet и показывает текущее
зарегистрированное состояние и record-only предупреждение Round 7.

**Граница применения:** модель оценивает появление новой записи
«Неисправен» в журнале за следующие 24 часа, а не подтверждённую
физическую поломку. Онлайн-расчёт не является подтверждением достижения
целевых офлайн-метрик;
автоматических уведомлений и действий нет. Предупреждения Round 7 являются
исследовательскими и требуют проверки оператором.
Расчёт признаков из нового загруженного журнала ещё не прошёл независимую
сверку с обучающим конвейером на реальном потоке; этот runtime-срез нельзя
считать готовой промышленной системой предупреждения.

## Запуск

Нужны Python 3.14, Node.js и 7-Zip (`7z` в PATH) для архивов `.7z`.
В PowerShell из корня проекта:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
cd backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Во втором окне:

```powershell
cd frontend
npm ci
npm run dev
```

Откройте `http://127.0.0.1:5173`. API доступен на
`http://127.0.0.1:8000/docs`. При первом импорте загрузите журнал и **оба**
справочника каналов и объектов. Сервис не подставляет тестовые справочники
вместо реальных. Большой исходный датасет и обучающая выборка в Git не
входят; для запуска интерфейса они не требуются. Небольшой проверенный файл
весов и его метаданные находятся в `backend/data/model/current/`.

Рабочие данные, загруженные справочники и журналы импорта сохраняются под
`backend/data/` и исключены из Git. Чтобы указать другую папку хранения,
задайте `DATA_DIR` в `backend/.env` (образец: `backend/.env.example`).

После каждой загрузки CSV/7z сервис сохраняет сырые события в Parquet и
пересчитывает Round 7 для последнего завершённого часа каждого затронутого
канала. Текущий час не закрывается искусственно. В расчёт попадает только
история до времени прогноза; автоматические действия не выполняются.
Периодическая выгрузка сама по себе не доказывает непрерывность канала, поэтому
результат остаётся исследовательским и не является заявлением о физической
неисправности.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r backend\requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s backend\tests -p "test_*.py" -q
.\.venv\Scripts\python.exe -m unittest ml.experimental_round7.test_models -q
cd frontend
npm run build
npm run lint
```

Исследовательские отчёты, исходные архивы, полная история и код повторного
обучения остаются в ветке `ML` и локальных артефактах, а не в этом runtime
срезе `main`.

В `ml/experimental_round7/` сохранены веса и код статического скоринга
кандидата Round 7. API использует эти веса для причинного расчёта из сырых
сообщений, но опубликованные офлайн-метрики Round 7 не считаются онлайн-
гарантией: они зависят от полного архивного допуска и отдельной
хронологической приёмки.
