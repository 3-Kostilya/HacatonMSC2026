# Milestone 1: подготовка событий в Parquet

> Обновление B1 от 2026-09-22: новый аудит текущих исходников и связи с объектами описан в [отчёте B1](ml-m1-b-review.md). 2021 год исключён по указанию пользователя. Ниже сохранён исторический отчёт прежнего прогона.

Реализована цепочка «источники → нормализация → справочники → Parquet → отчёт
качества». Проверка выполнена на ограниченном объёме из всех доступных источников.
Полная история и заявленные в ТЗ 313 млн строк ещё не обработаны этим pipeline;
приёмка на полном масштабе остаётся отдельным подэтапом M1. Никаких новых признаков,
детекторов, псевдометок или моделей в этой работе не реализовано.

## Что переиспользовано

- Правила разбора времени, чисел и флага тревоги из `stage1/normalization.py`.
- Поиск 7-Zip и разбор состава архивов из `analysis/audit_stage1_sources.py`.
- Существующие справочники, аудит источников, паспорта типов и тестовый каркас.
- Прежние детекторы и исследование дымовых датчиков сохранены. Их результаты
  и target «Неисправен» не считаются разметкой физического отказа нового решения.

Работа разделена между субагентами: потоковое чтение источников; справочники
и их проверки. Основной агент собрал pipeline, выполнил сквозные проверки и исправил
замечания независимого ревью.

## Контракт и сохранность

Все шесть исходных значений сохраняются как текст, вместе с именем файла и номером
логической CSV-записи. `timestamp` — локальное время журнала без присвоения часового
пояса. Исходное значение разделяется на `value_raw`, `value_numeric`, `value_state`
и `is_numeric`. Числа `-3276`, `327.68`, `999` не удаляются; `NaN` и бесконечность
сохраняются текстом с флагом `nonfinite_numeric`.

Полным дубликатом считаются совпадающие шесть исходных полей, включая ID события.
Проверка действует между файлами и пакетами; один и тот же ID с другими данными
сохраняется. Повторные заголовки исключаются из чистой истории. Строки с невалидным
временем/флагом тревоги, пустым каналом или значением помещаются в карантин.
Исключённые записи сохраняются в `excluded_rows.parquet` с причинами; у дубликатов
есть ссылка на первую запись. Нарушенная структура CSV прерывает прогон, чтобы
не угадывать границы полей.

Неизвестные каналы и разные значения одного канала в один момент сохраняются
с флагами качества. Последний случай ещё не означает неисправность или ошибку:
возможны несколько сообщений в пределах точности часов журнала.

Соединения со справочниками не размножают строки. Связь с объектом выполняется
только по настоящему ключу. Различаются неизвестный канал, отсутствие колонки
связи, пустая ячейка связи и отсутствующий объект. Связи по названиям не угадываются.

Каждый месячный файл отсортирован по `channel_id`, `timestamp`, `row_id`.
Конкатенация файлов разных месяцев не является глобально отсортированным потоком:
читатель истории канала должен явно упорядочить её. При реальном прогоне обнаружена
и исправлена перестановка блоков при partitioned COPY; теперь каждый месяц
записывается отдельным упорядоченным запросом. Регрессионный тест использует
300 000 строк и несколько блоков на файл.

## Артефакты и проверки

- `manifest.json`: конфигурация, объём реально прочитанного, версии библиотек,
  SHA-256 источников и справочников, статус прогона.
- `clean/year=.../month=.../data_0.parquet`: нормализованная история.
- `excluded_rows.parquet`: исключённые исходные записи, причины и происхождение.
- `sensor_statistics.parquet`: количество событий, числовых/текстовых значений,
  тревог, границы истории и количество уникальных значений для каждого канала.
- `sensor_family_report.csv`: распределения типов, числовых значений и тревог.
  Количество кандидатов намеренно отсутствует: детекторы ещё не запускаются.
- `data_quality.json`: распределения по типам/месяцам, качество и размеры файлов.

Прошли 124 теста `stage1` (20 новых) и 25 тестов `analysis`, Ruff check и format.
Сквозные тесты покрывают дубликаты между файлами/пакетами, повторный ID, повторный
заголовок, подозрительные значения, карантин, неизвестные каналы, конфликты времени,
связи объектов, пустые данные, сортировку и непубликацию неуспешного результата.

Реальный прогон прошёл шесть sanity checks: баланс входных/выходных строк,
сохранение кардинальности при соединениях, согласованность представления значений,
уникальность происхождения принятых записей, совпадение физических размеров
Parquet по числу строк и фактический порядок записей внутри файлов.

## Память, запуск и оставшиеся ограничения

История не собирается в pandas. Python держит пакеты по 25 000 строк; DuckDB
хранит промежуточные таблицы на диске и использует каталог временного сброса.
В настройках DuckDB установлен лимит 512 MB. Это не измеренный пик RAM всего
процесса и не доказательство работоспособности на 313 млн строк. Полный прогон
должен отдельно подтвердить время, пиковую память и временный расход диска.

Результаты сначала создаются в каталоге `<output>.inprogress`. Только после
проверок каталог переименовывается в итоговый. Ошибочный прогон остаётся в
`.inprogress` с `status=failed`; потребителям разрешены только завершённые
результаты с `status=complete`. Уже существующие каталоги не перезаписываются.
Автоматического возобновления неполного прогона пока нет. Контрольная сумма каждого
источника повторно проверяется после чтения.

```powershell
# Повторный ограниченный прогон — обязательно в новый каталог
python -X utf8 analysis/prepare_ingestion.py --output output/milestone1/recheck

# Полное чтение перечисленных в конфигурации источников: подэтап M1.5
python -X utf8 analysis/prepare_ingestion.py --full --output output/milestone1/full
```

Архив 2021 отсутствует. В справочнике каналов нет `ид_объект`, поэтому 855 691
запись известных каналов имеет статус `object_mapping_unavailable`; объектные
признаки в будущем потребуют настоящего соответствия канал → объект. У 95 объектов
есть отсутствующий родитель `3831`; циклов иерархии не найдено. Нулевое число
невалидных внешних ключей каналов не означает наличие объектного покрытия.

Неудачный первый прогон `output/milestone1/pilot` оставлен для диагностики;
его файлы не использовать. `pilot_verified` — промежуточная успешная проверка.
Актуальный результат после исправлений ревью — `verified`.
