# R4 B — первое сравнение условных дискретных baseline

Использован совместный контракт R3
`ml/r3_conditional_training_contract_v1.json` и ровно 51 признак из списка A
`r3-a-discrete-baseline-features-v1`. Локальный результат и модели находятся
в `output/r4-b-conditional-discrete-baselines-20260925-v5/`; файлы
`output/` не входят в Git. Скрипт
`analysis/train_r4_discrete_baselines.py` сверяет SHA-256 входов и
месячных частей и отклоняет намеренно исключённый год.

Цель — новое **зарегистрированное сообщение** «Неисправен» в следующие
24 часа при операционном предположении о полноте архива. Непрерывная работа
канала и физическая поломка не подтверждены. Обучение использует только
train; весь условно допущенный validation служит для сравнения и выбора
временного порога. Test не использовался для обучения, подбора или оценки.

В train взяты все 6 871 положительных часов и воспроизводимая 2%-я
выборка отрицательных: 130 121 из 6 498 173, всего 136 992 строки.
Категориальное кодирование и заполнение пропусков логистической регрессии
обучены только на train. CatBoost использует тот же набор часов.
Вероятности после такой выборки и балансировки классов не калиброваны.

На validation — 1 365 077 часов, из них 1 943 положительных из 261
эпизода; 117 266 наблюдаемых канал-дней. Все методы оценены на одних
и тех же строках. Порог каждого метода выбран по максимуму часового F1
на validation, поэтому пороговые показатели могут быть оптимистичными.

| Метод | PR-AUC | Precision / Recall по часам | Recall эпизодов | Ложноположительных часов / 1000 канал-дней |
|---|---:|---:|---:|---:|
| Простое правило прошлого отказного текста и завершённых эпизодов | 0,1941 | 0,2076 / 0,4436 | 0,4483 | 28,1 |
| Logistic Regression | 0,0987 | 0,1250 / 0,6593 | 0,7050 | 76,5 |
| CatBoost | 0,1194 | 0,1512 / 0,6320 | 0,6475 | 58,8 |

Правило получает фиксированный score:
`2 × registered_fault_text_count_24h +
0,5 × registered_fault_text_count_168h +
completed_episode_count_168h +
0,1 × technical_message_count_24h`.
Каждое поле описывает только прошлое к моменту прогноза. Показатель
ложноположительных часов пока не является числом отдельных тревог:
соседние часы одного канала здесь не подавлены.

Детализация по типам находится в `report.json`. Положительные
validation-эпизоды сосредоточены у дымовых датчиков (118) и «Состояния
фазы» (116); у ИБП их 17, у газовых датчиков 4. Для редких типов
отдельные оценки неустойчивы, а для типов без положительного класса
PR-AUC не определена. Сильный общий результат простого правила,
особенно на дымовых датчиках, требует отдельного аудита связи
предыдущих сообщений с последующим эпизодом; прежний отказ не
превращается автоматически в доказанную физическую неисправность.

Повторный запуск с фиксированным порядком обучающих строк дал те же
глобальные метрики. SHA-256 итогового локального `report.json`
записан в соседнем `manifest.json`.

Воспроизведение из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -B analysis/train_r4_discrete_baselines.py `
  --a3-dir output/r3-a-full-months-20260924 `
  --b3-dir output/r3-b-full-months-20260925-v2 `
  --index-dir output/r3-b-conditional-discrete-20260925 `
  --output-dir output/r4-b-conditional-discrete-replay
```

**Статус R4:** первая техническая validation-сверка выполнена; совместная
приёмка R4 и выбор финального метода ещё не сделаны. Следующие проверки —
причинность и качество правила на трассах, бюджет отдельных тревог с
подавлением повторов, стабильность по времени и типам, ресурсный
batch/replay-контроль A. Закрытый test открывать только после
заморозки метода и порога.
