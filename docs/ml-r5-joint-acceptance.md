# R5 — независимая проверка A и техническое закрытие

**Решение A:** подтверждаю завершение R5 как отрицательного
validation-эксперимента. Новые блоки признаков не заменяют правило R4
для R6 при сопоставимой нагрузке предупреждений. Это не утверждение,
что признаки бесполезны при любом пороге или в иной задаче.

B завершил [абляцию](ml-r5-b-ablation-review.md) на полном
[пакете A](ml-r5-a-anomaly-handoff.md) в коммите `79e468b`. A независимо
запустил опубликованный код на тех же локальных A3, R3/B, R5/A и R4
источниках. Повторились 136 992 train-часов (6 871 положительный) и
все 1 365 077 validation-часов (1 943 положительных из 261 эпизода).
Ни один test-час или test-target не использован для обучения,
выбора признаков, порога либо этой приёмки.

## Что сверено

- Во всех 12 validation-месяцах ключи, метки и эпизоды B совпали с
  принятым R4 построчно. Базовый балл CatBoost совпал точно:
  максимальная абсолютная разница `0`.
- По нескольким ключам каждого месяца перепроверены 69 строк из исходных
  A3/R5 и сохранённых моделей. Максимальная разница между batch и
  повторным прогнозом всех семи вариантов — `0`.
- Отдельный пересчёт порогов и 24-часового подавления дал для правила
  R4 **78 эпизодов / 177 лишних предупреждений**; для сильнейшего
  R5-варианта «кластеры + переходы» — **79 / 234**. На испытанной
  сетке порогов при не более 177 лишних предупреждениях последний
  даёт **58 / 177**, полный набор — **60 / 172**. Правило сохраняет
  **78 / 177**. Сетка порогов не доказывает глобальный оптимум по всем
  вещественным значениям.
- Подтвердились 7 из 12 месяцев с более высоким PR-AUC варианта
  «кластеры + переходы» относительно CatBoost R4, но типовые
  сдвиги неоднородны: у дымовых датчиков 33 найденных эпизода у
  правила против 18 у R5; у «Состояния фазы» — 40 против 57.
  Из 79 R5-эпизодов 47 общие с правилом, 32 новые, 31 найденный
  правилом пропущен.
- Пропуски новых признаков не удаляли строки. У IF есть оценки для
  всех validation-часов; у блока переходов — для 1 302 408 из
  1 365 077. Анализ на общей области не подменяет основную оценку.

Проверка A сохранена локально в
`output/r5-a-independent-review-20260925/report.json`; повторный
расчёт B и устойчивость — в
`output/r5-a-independent-replay-20260925/` и
`output/r5-a-independent-stability-20260925/`. Эти данные остаются
в игнорируемом Git `output/`; код проверки —
`analysis/audit_r5_joint.py`.

**Ограничение по артефактам:** оригинальный `output/` B не передан A.
SHA-256 манифеста независимого прогона A
`38fa5b5d98b574504af7a14f92b329a98334cd1f366a187b1bec5a60fa37d694`
не совпал с закреплённым B
`5b0af2e8f697517a7d7a41d9ba13ca1b1b9d890548d9ee0a8338730e9d3af287`.
Поэтому A подтверждает воспроизводимость указанных чисел и
построчных проверок, **не побайтовое тождество** отсутствующего
пакета B. Причина различия хешей не установлена; при передаче
оригинальных файлов их можно сверить отдельно.

Исследовательский лимит 2 лишних предупреждения на 1000 канал-дней
не утверждён заказчиком. Окончательный порог, единичный закрытый
test и ресурсный inference-пакет остаются R6. Цель по-прежнему
будущая зарегистрированная запись «Неисправен» при условном
предположении о полноте журнала, не подтверждённая физическая
поломка.
