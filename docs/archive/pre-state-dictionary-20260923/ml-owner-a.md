# Участник A: данные, признаки и детекторы

Это задание друга (участник A); пользователь выполняет роль B.

Общий план: [ml-two-person-plan.md](ml-two-person-plan.md).
Ты отвечаешь за левую часть ML-цепочки и её интеграцию; участник B параллельно
готовит синтетику/оценку, затем разметку и прогноз. Веб-разработка не входит.

## Первое задание

Согласуйте M0: одну Git-ревизию, схемы событий/часовых признаков/scores,
временные границы и небольшой общий набор. Затем проверь существующий
`stage1/ingestion/` и выполни полный прогон доступных исходников. Не переписывай
готовую нормализацию, если её контракт и тесты подходят.

Передай B manifest и отчёт: сколько прочитано/принято/исключено, распределения
по типам и месяцам, неизвестные каналы, качество связей, размеры, время и память.
Укажи отсутствующий 2021 год и отсутствие ключа канал → объект. Прогон на
869 993 строках — уже имеющаяся проверка, а не обработка всей истории.

## Последовательность задач

| ID | Что сделать | Что передать B | Когда можно считать готовым |
|---|---|---|---|
| A1 | Довести текущий ingestion до полного доступного объёма | Clean Parquet, manifest, data quality | Баланс строк и связей, ресурсы и воспроизводимость проверены |
| A2 | Часовая сетка; окна 1/6/24/168h; numeric/state/mixed; baseline и доступность | Версионированные hourly features | Проверены 20 каналов и причинность; пустое не равно нормальному |
| A3.1 | Отдельные level/drift/variance, change point; исправление статичной опоры | Scores по каждому правилу, evidence | Проходят собственные тесты; B может независимо оценить |
| A3.2 | IF, MiniBatchKMeans/HDBSCAN, переходы режимов | Scores и обученные преобразования | Fit без будущего, методы сопоставлены на одинаковой выборке |
| A4 | Исправления по tuning, заморозка детекторов | Версия кода/параметров для закрытой оценки B | Условия допуска из общего протокола соблюдены |
| A5 | Общий anomaly score и исторический расчёт | Полные scores с доступностью и свидетельствами | B может воспроизвести эпизоды замороженным разметчиком |
| A6 | Признаки по временным фолдам; адаптер inference | Причинные feature packs | Совпадают batch/replay, будущие записи не меняют прошлое |
| A7 | Ablation, масштабирование и интеграция признаков с моделью B | Таблица экспериментов, единый расчёт | Финальная схема совпадает с train; ресурсы измерены |

## Границы работы

Твои файлы: `stage1/ingestion/`, новые `stage1/features/`,
`stage1/anomaly_models/`, существующие `profiles.py`, `detectors.py`,
основной `stage1/pipeline.py` и скрипты подготовки.
Модули эпизодов/разметки/прогноза принадлежат B; подключай их через контракт.
Изменения общих схем, наблюдаемости и зависимостей сначала согласуйте.

Каждой задаче нужны тесты, команда воспроизведения и маленький отчёт.
Не используй hidden synthetic labels, будущие состояния, ID/имена источников
как признаки. Не учи scaler/кластеризацию на полной истории до временного split.
Не трактуй номер кластера или редкий режим как отказ. Не придумывай объектные связи.

Не жди готового прогноза: твою работу проверяет стенд B. Не переходи к массовой
псевдоразметке до приёмки M4. После каждого milestone вместе принимаете результат.
