# Q2/A: повторное предупреждение после наблюдённого восстановления

Дата: 27.09.2026. Основание — [позиция B](ml-q2-b-episode-alert-position.md),
`bc68b40`. Работа выполнена в отдельной рабочей папке на **той же ветке ML**;
ветка и файлы параллельного `codex/ml-experiment` не переключались.

## Решение A

**Подтверждаю причинную реализуемость кандидата для отдельного офлайн-протокола B.**
Реальные последовательности позволяют оценить повторный риск после уже
наблюдённого нового «Неисправен» и бесконфликтной «Норма». Условие не
требует будущей метки и воспроизводится после перезапуска.

Это **не утверждение рабочего правила**, не достижение требований и не
предметное подтверждение полезности повторных уведомлений. По R1 показаны
различные зарегистрированные эпизоды; доказать отдельные физические поломки
или пользу оператору из журнала нельзя. Короткие эпизоды не объединялись.
R1/B3, опубликованные Q2/R6, метки, допуск и прежний test не изменены.
Кандидат находится только в `analysis/`, не подключён к рабочему прогнозу.

Для дальнейшего сравнения B сначала фиксирует отдельный протокол на
внутренних временных частях train. Таблица validation ниже — диагностика,
не выбор правила/порога и не независимое подтверждение качества.

## Условие кандидата

При активном 24-часовом подавлении повтор разрешён только если:

1. После прежнего предупреждения на том же канале уже наблюдалось уверенное
   по R1 начало: `warning_time < onset_time <= warning_time + 24h`.
2. Затем до нового прогноза получена строго более поздняя точная «Норма»
   без конфликта/неопределённости. Спорная секунда и смена типа не подходят.
3. На новом часе прежний причинный QA-допуск Q2 опять `eligible`, тип тот
   же, активного эпизода нет, сырое состояние согласуется с прошлым допуском.
4. Прежняя модель превышает **тот же опубликованный порог**. Одна «Норма»,
   повторный высокий балл без наблюдённого эпизода, молчание и `alarm=false`
   сами по себе подавление не снимают.

После выданного повтора начинается новый отсчёт; свидетельство восстановления
потребляется один раз. Позднейшая неопределённость аннулирует свидетельство.
Через исключённый 2021 год ни эпизод, ни разрешение повтора не переносятся.

Использован принятый `EpisodeBuilder` только на **уже прочитанных закрытых
группах секунды**, без полного B2-каталога. Будущие окончательные статусы
эпизода заранее не читаются. Интерфейс решения принимает только прошлые
поля допуска и булево превышение балла; `target`, ID будущего эпизода и
другие поля меток отклоняются. Физическая доступность остаётся `unknown`;
полнота архива — допущение. Прежний QA-допуск здесь — отдельный ранее
проверенный прошлый вход, а не повторный полный расчёт признаков.

## Данные и технические проверки

- Проверены хеши всех **72 M1-файлов**: 2019, 2020, 2022–2025. 2021 и
  события test 2026 не использовались.
- Выделено **742 581 текстовое сообщение на 744 каналах**: 743 канала с
  баллом выше прежнего порога и защищённый температурный `228571`.
  До последнего решения в причинный автомат вошли **738 353** сообщения.
  Остальные каналы не пересчитывались; полного повторного ingestion нет.
- Группа секунды обрабатывается целиком; `row_id` — идентичность, не порядок.
- Все **6 973** часа выше порога совпали с сохранённым причинным допуском
  Q2 и состоянием из сырого журнала. Нижние баллы не могут выдавать
  предупреждение: их тяжёлые признаки для сравнения правил не нужны.
- Контроль воспроизвёл прежние 1 305 предупреждений, 346 совпадений и те
  же ключи канонического оценщика B.
- Все 6 973 решения совпали с расчётом, возобновляемым из JSON между
  месяцами. В **12 контрольных точках** совпало полное состояние.
- Все 329 досрочных предупреждений имеют проверенные прошлые начало,
  восстановление и допуск. Полные свидетельства сохранены.
- На `228571` прочитано 44 684 текстовых сообщения, но решений для него
  нет. Защитный запрет сохранён; его эпизоды не убраны из Recall.

Будущие метки подключаются **после фиксации решений**, только для оценки.

## Диагностический результат

Сохранённая линейная модель, 121 поле, порог `0.9993761875927455`.
Популяция прежняя: 13 945 520 назначенных бинарных часов / 715 133 канал-дня.
Recall — от **всех 2 142 эпизодов**. Неизвестные метки не превращены в ноль
и по-прежнему отсутствуют в этой ретроспективной оценке предупреждений.

| Предупреждения | 1 305 | 1 605 |
| Найденные эпизоды | 346 | 504 |
| Без нового целевого эпизода | 959 | 1 101 |

Найдены 160 ранее пропущенных эпизодов, потеряны 2 прежних: **нетто +158**.
Из 329 досрочных предупреждений 183 совпали с новым эпизодом, 146 — нет.
Общий прирост предупреждений — 300: изменились и некоторые последующие
обычные 24-часовые моменты. Второй TP одному эпизоду не начислялся.

Все типы, включая типы без положительных эпизодов, учтены в JSON; суммы

на 1 000 канал-дней» не является согласованным заказчиком лимитом.

## Что означают реальные короткие трассы

Медианная длительность эпизода перед досрочным повтором — **12 секунд**,
минимальная — 1 секунда. Все 329 повторов выданы в пределах часа после
восстановления; минимальная задержка — 0 секунд на закрытой секунде целого
часа. Это соответствует офлайн-контракту, не реальному времени доставки.

Пример: канал `229667` («Состояние фазы»), 06.01.2025:
17:00 предупреждение → 17:00:33 «Неисправен» → 17:00:37 «Норма» →
18:00 повторное предупреждение. На журнале условие причинно. Считает ли
оператор четырёхсекундное состояние самостоятельным инцидентом и полезен
ли повтор через час — остаётся предметным вопросом.

Для ревью сохранены первые по времени три трассы каждого сработавшего
типа, всего 10, **без выбора по истинному/ложному исходу**. В примерах только
прошлые текстовые сообщения до нового предупреждения. Числовые показания
и объектные связи заново не расшифровывались. Синхронные газовые сообщения
не удалялись и не объявлялись обслуживанием.

## Следующее действие B и совместной части

B независимо сверяет replay и готовит **отдельный протокол внутренних
train-проверок** до выбора правила/модели/порога. A/B уточняют полезность
коротких повторов и нагрузку по [предметным вопросам](ml-q2-episode-alert-questions.md).
Для независимой оценки нужны не использованные ранее исходы.
Precision > 0,7 / Recall > 0,5 не достигнуты; живой пилот не разрешён.
