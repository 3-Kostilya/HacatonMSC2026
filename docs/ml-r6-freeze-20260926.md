# R6 — зафиксированное решение до закрытого test

**Метод:** принятое в R4 простое правило по прошлым зарегистрированным
состояниям. В R5 дополнительные методы не улучшили эпизодный результат
при сопоставимой нагрузке. Это *score будущей записи «Неисправен» в журнале*
на условно допущенных каналах; он не является калиброванной вероятностью
физической поломки.

## Решение по QA до выбора порога

Отдельное QA-наложение A воспроизведено из тех же M1/A3 без изменения
исходных файлов: 13 ранее не исключённых сообщений изменяют 3 948
часовых строк A3. По принятому индексу R3 из них **99** находятся в
validation, **0** в train; среди этих 99 нет положительных часов.
Поключевая сверка старых и исправленных строк показала изменения
оконных счётчиков состояний и базового числа состояний, но **ни одно
из четырёх полей правила не изменилось**. Балл правила и переход через
порог 7,1 не изменились ни на одной исправленной строке. Отчёт:
`output/r6-b-qa-baseline-impact-20260926/report.json`.

Новые QA-счётчики A рассчитаны лишь для 3 948 исправленных ключей.
Включать их в модель или молча подменять отсутствующие нулём нельзя.
Для этого потребовались бы полный причинный расчёт по выбранной
популяции, новая версия признаков и новая validation-проверка.
Поэтому QA-счётчики остаются диагностикой, а принятое правило R4
не переобучается. Отрицательные показания газа и другие QA-кандидаты
не становятся метками физического отказа. 2021 год исключён.

## Заморозка на validation

Версия и точная формула записаны в `ml/r6_frozen_rule_v1.json`:

```text
score = 2 × registered_fault_text_count_24h
      + 0,5 × registered_fault_text_count_168h
      + 1 × completed_episode_count_168h
      + 0,1 × technical_message_count_24h
```

Прогноз разрешён только для строк с явным статусом `eligible`; для
`unknown` и `excluded` score отсутствует, а не равен нулю. Порог
**7,1** выбран на validation по максимуму найденных эпизодов при
исследовательском пределе **2 лишних предупреждения на 1000 канал-дней**
с 24-часовым подавлением повторов. Пользователь подтвердил использование
этого предела *для исследования*; заказчик эксплуатационную нагрузку
не утверждал. Порог не является утверждённой настройкой продукта.

До открытия test повторно рассчитаны баллы всех **1 365 077**
validation-часов. Они побайтово по числам совпали с принятой оценкой
R4: максимальная разница балла **0**. Порог 7,1 даёт **78 из 261**
эпизода и **177** предупреждений без нового эпизода, или **1,509 на
1000 канал-дней**. QA-наложение этот результат не меняет. Протокол:
`output/r6-b-validation-freeze-20260926/report.json`.

Файл заморозки фиксирует версии A3, R3, QA-аудита, формулу, горизонт
24 часа и порог до единственного чтения закрытых меток test.
Разработан отдельный scorer `ml/forecast/r6_rule.py` и скрипт
`analysis/score_r6_sealed_test.py`; синтетические проверки выполнены
до запуска на реальном test. После заморозки модель, критерий и порог
не изменять по результату test. Для production ещё нужны проверенный
путь история → признаки, ресурсный batch/replay и утверждённый
допустимый бюджет предупреждений.
