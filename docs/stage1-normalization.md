# Потоковая нормализация событий — День 2

Дата проверки: 19 сентября 2026 года.

## Результат

`stage1/normalization.py` задаёт один входной конвейер для всех 19 типов и семи
групп. Он принимает итератор чанков, хранит в оперативной памяти только текущий чанк,
а узкий индекс для межчанковых проверок размещает во временной SQLite-базе. После
завершения вызова временный файл удаляется.

На выходе `NormalizationResult` содержит исходный файл и фактический номер строки,
статус обработки и совместимый `NormalizedEvent`. Отбракованные строки остаются в
потоке аудита с `event=None` и причинным флагом. Поле `event_id` сохраняется, но не
используется как единственный ключ.

## Правила без неявных догадок

- Время собирается из `дата` и `время` через ISO-разбор и хранится как локальное
  naive-время. Значение с часовым поясом получает `timezone_present` и отклоняется.
- Допустимые тревожные значения: `true/t/1` и `false/f/0`, без учёта регистра и
  крайних пробелов. Другое значение получает `invalid_alarm` и отклоняется.
- `raw_value` сохраняет исходный текст без замены. `numeric_value` заполняется
  отдельно для конечного числа с точкой или десятичной запятой. Текст не
  интерпретируется как физическое состояние; `NaN` и бесконечности не входят в
  числовой ряд и получают `nonfinite_numeric`.
- Канал вне текущего справочника не теряется: тип становится `unknown`, добавляется
  `unknown_channel`.
- Пустой ID события допустим с `missing_event_id`, потому что ID не является
  достаточным ключом. Пустой канал, значение, неверные время или тревожность делают
  строку `rejected`.

Точный дубль — только более поздняя строка, у которой одинаковы все шесть исходных
полей журнала после CSV-декодирования: ID события, ID канала, дата, время, тревожность
и значение. Сравнивается каноническая сериализация самих полей, не короткий хеш.
Первое вхождение имеет `accepted`, последующие — `exact_duplicate` и ссылку на
источник/строку первого. `iter_accepted` исключает их явно.

Конфликт — разные пары `(исходное значение, разобранная тревожность)` одного канала в
один момент. Все варианты сохраняются и все получают `channel_time_conflict`; выбор
одного варианта запрещён. Разные ID с одинаковой семантической парой не считаются
конфликтом и не считаются дублем, если остальные исходные поля различаются.

Duplicate/conflict-аудит глобален для одного вызова `normalize_chunks`, включая все
переданные ему чанки. Если источники нормализуются отдельными вызовами, сравнение
между ними намеренно не происходит; вызывающий код должен передать их одним потоком,
когда требуется поиск межфайловых повторов.

## Ограниченный реальный проход

`analysis/prepare_stage1_sample.py` читает CSV или единственный CSV внутри 7z
последовательно, не распаковывает архив на диск и не загружает его целиком. Для
каждого типа выбирается не более двух каналов. Parquet создаёт только CLI; библиотечный
API от формата хранения не зависит.

Проверочный запуск прочитал не более 5 000 000 входных строк из каждого из двух
источников — файла-примера и архива 2026 года. Получен
`output/stage1/normalized_sample.parquet`:

- 5 585 выходных строк, две Parquet row group;
- 19 из 19 типов имеют реальные строки, включая 20 строк `9-секционного люка`;
- выбрано не более двух каналов каждого типа;
- в этой адресной выборке 5 585 строк `accepted`, отклонений и точных дублей нет;
- реальные номера строк сохранены: например, последние выбранные строки архива
  находятся около номера 4 999 556, а не перенумерованы внутри подвыборки;
- Parquet содержит раздельные `raw_value` и `numeric_value`, а также источник,
  исходную строку, статус, alarm и список флагов.

Это техническая адресная выборка для проверки конвейера, а не оценка частот типов,
состояний или качества всего архива. Сильное преобладание газовых строк в ней нельзя
экстраполировать на генеральную совокупность.

## Воспроизведение

```powershell
python -X utf8 -m unittest stage1.test_normalization -v
python -X utf8 analysis/prepare_stage1_sample.py `
  --input data/журнал_событий_пример.csv `
  --input data/ext-journal-2026.7z `
  --max-input-rows 5000000 `
  --output output/stage1/normalized_sample.parquet
```

Рядом с Parquet создаётся `normalized_sample.manifest.json` с выбранными каналами,
строками по каждому типу, статусами и списком типов без данных.
