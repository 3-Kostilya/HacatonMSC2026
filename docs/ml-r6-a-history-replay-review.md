# R6/A — независимое воспроизведение истории и ресурсов

Дата: 26.09.2026. **Части A и B выполнены; совместная техническая приёмка R6
закрыта, включая сверку переданных оригиналов B.** Это не разрешение на эксплуатацию
и не проверка физической поломки. Решение B `4354fb3`, формула и порог 7,1
не изменены после открытия test.

## Что проверено

Для всех **1 318 741** допущенных test-часов января–июня 2026 независимо
восстановлены четыре входа выбранного правила непосредственно из M1
и проверенного каталога B2:

- число зарегистрированных сообщений «Неисправен» за 24 и 168 часов;
- число технических сообщений за 24 часа;
- число бесспорно завершённых эпизодов за 168 часов.

Новая SQL-проверка не вызывает старый расчёт R2/A3. Семантические правила
R1 и консервативный адаптер завершённых эпизодов B2 общие: их версии и
происхождение проверены. В таблицу ключей для расчёта признаков входят
**только канал и время**; будущие метки не передаются. Окна `(t-H,t]`,
завершения эпизодов учитываются только при `end_at<=t`, конфликтующие
сообщения исключаются по прежнему правилу. Вспомогательный CSV-пример и
2021 год не входят в историю.

По каждому из четырёх входов расхождений с A3 — **0** на всей допущенной
популяции. Независимая арифметика совпала с зафиксированным scorer.
Другая, последовательная Python-реализация `iter_rule_history` проверена
на **543 часах / 341 канале**: первые/последние часы каждого месяца и типа,
час с наибольшим прошлым score и три ключа по хешу. Дополнительный отбор
не использует target. Для всех 543 часов совпали пакетный расчёт,
одиночный снимок и расчёт на обрезанной истории; добавление события после
прогноза не меняло прежние признаки. Оба способа подавления повторов
совпали на **310 предупреждениях**, включая перенос 24-часового cooldown
через границы месяцев.

Входная история — семь месячных Parquet M1 (декабрь 2025 — июнь 2026;
35 389 345 строк по метаданным файлов). Для выбранного правила достаточно
прошлых 168 часов: фактический диапазон от 25.12.2025 до последнего
допущенного часа 29.06.2026 23:00. Отдельно зафиксированы SHA-256 этих
семи Parquet. Многогигабайтные CSV и все 259 млн строк повторно не читались.

## Результат и ресурсы

Точно воспроизведены опубликованные B результаты при **неизменном** пороге:
100 из 489 доступных эпизодов, 210 несопоставленных предупреждений,
1,814 на 1000 допущенных канал-дней. Precision 32,26%, recall 20,45%,
F1 25,03%; почасовая PR-AUC 0,164638. Медианное упреждение — 0,496 часа.

Завершающий локальный запуск: **27,56 с**, пик рабочей памяти
**1 362 579 456 байт / 1,269 GiB**, DuckDB 2 потока и лимит 2 GB.
Время включает проверку входов, каталог B2, пересчёт четырёх признаков,
диагностический replay, запись прогнозов, метрики и хеширование источников;
не включает старт Python и загрузку модулей. Это не промышленный SLA.
Память опрашивалась раз в 50 мс, на Windows дополнительно учитывался
процессный peak working set. В отчёте записаны версии среды.

Исходную проверку истории сопровождали **268 тестов stage1, 103 анализа,
5 forecast**. Файловая сверка дополнительно покрыта девятью тестами:
перестановка строк, точное сравнение значений и null, несовпадения ключей,
дубли, схемы, хеши, выход пути за пакет и отбор только test перед join.

## Границы приёмки

1. Полностью проверены **четыре входа выбранного правила**, не все 111
   признаков A3 и не остальные модели R4/R5.
2. Оригиналы B проверены по ранее зафиксированным хешам, их поключевое
   содержимое сверено с A. Проверка оригиналов не означает побайтового
   тождества прогнозных Parquet A/B и не расширяет исследовательскую цель.
3. R3 — ретроспективный индекс оценки: он использует пригодность будущей
   метки. Его нельзя объявлять готовым правилом допуска для живого
   inference. Функция `iter_rule_history` формирует только прошлые входы;
   внешний вызов scorer обязан явно передать пригодность прогноза.
4. Прогноз относится к записи «Неисправен» в журнале при условном
   предположении полноты архива. Непрерывность работы канала, физическая
   поломка и пригодность неизвестных часов не доказаны. Доступны лишь
   9,38% часов A3; остальные не получают нулевой риск.
5. Бюджет предупреждений и реакция на них заказчиком не утверждены.
   Низкий recall, упреждение около 30 минут и высокая нагрузка отдельных
   типов не позволяют объявить продукт готовым к эксплуатации.

Таким образом, обязательная независимая техническая проверка A для
исследовательского R6 выполнена. Вместе с зафиксированным результатом B
и файловой сверкой это закрывает **совместную техническую приёмку R6**
в указанной области. Живой допуск и внедрение остаются отдельными
незакрытыми вопросами.
