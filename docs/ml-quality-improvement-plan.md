# Улучшение качества после R6 — эксперименты Q1/Q2

Дата: 26.09.2026. Работа в единственной ветке `ML`. Замороженный R6 и его
test не меняем. Технический перезапуск A/B принят B (`895e225`), но это
не достижение требований к качеству. Живой P3 остаётся отдельной задачей.

## Цель и критерии

Исходное задание: Precision > 0,7, Recall > 0,5, горизонт 24 часа. Цель
текущей исследовательской версии — новое зарегистрированное «Неисправен»,
не физическая поломка. Числовые аномалии/QA-коды не создают target.

При материализации A единица оценки ещё ожидала совместной сверки. Затем
B опубликовал [протокол ML v2](ml-v2-experiment-protocol-b.md), коммит `9913c64`:
основные цели считаются по предупреждениям/эпизодам, Recall — по всем
назначенным положительным эпизодам, включая недоступные модели.
A принимает такое разделение; почасовые показатели публикуются отдельно.
Для предупреждений сохраняем одну связь с эпизодом, 24-часовой cooldown,
нагрузку и упреждение; охват обязательно показываем рядом с метриками.
Согласование эксплуатационных условий с заказчиком остаётся отдельным решением.

## Порядок

1. **Q1/A — данные для нового эксперимента.** На всех 72 train/validation
   месяцах (2019, 2020, 2022–2025) исследовать причины прошлой пригодности
   A3, отдельно от пригодности будущей метки. Материализовать 20 причинных
   QA-счётчиков по пяти категориям и четырём окнам на всех прежних условно
   допущенных ключах R3. Применить опубликованные QA-коррекции к 51 базовому
   признаку. Не трогать исходные пакеты и файлы test 2026 года.
2. **Q1/B — протокол и сравнение.** Принять новый allowlist и пакет A,
   согласовать QA-гейт и определение метрик. Сравнить исходные признаки,
   исправленные признаки и исправленные признаки + QA на одной популяции;
   подобрать модели/порог только на train/validation. При отсутствии выигрыша
   оставить базовый метод, а не объявлять новые признаки полезными заранее.
   Если исправленная и исходная базы совпадают, проверить это и не дублировать
   обучение идентичных вариантов.
3. **Q2/A+B — охват.** По результатам аудита отдельно предложить новые
   причинные ветви допуска (например, для числовых каналов), совместно
   утвердить популяцию и метки. `unknown` не превращать в отрицательный класс,
   не снимать проверки только ради увеличения Recall. Q1 не расширяет допуск.
4. **Q3 — новая независимая оценка.** Зафиксировать выбранный вариант до
   новых исходов. Открытый test R6 не использовать для настройки или как
   «новый закрытый test». При нынешних файлах можно получить исследовательский
   validation-результат, но не новую независимую гарантию качества.

Train — до 01.01.2025, validation — 2025 год; исключённый 2021 год не
переносит историю. Будущая метка и её пригодность не входят в признаки.
Старый R3-индекс используется только как уже принятая **ретроспективная
сравнительная популяция**, не как живой допуск. A в feature-запросе читает
из него только ключи и тип; метки, split и ID будущего эпизода остаются у B.

Новые QA-счётчики учитывают уже полученные сырые наблюдения, включая записи
с флагами качества: это диагностические счётчики, не физическая статистика.
Прежние физические числовые/дискретные признаки исправляются отдельным
проверенным наложением. При нарушении дискретной пригодности после QA
публикуется отдельная причина; такая строка не становится автоматически
допустимой для новой модели. Все результаты Q1 — вне Git в `output/`.

## Владельцы и передача

A — аудит, материализация, происхождение, проверки окон и будущего хвоста.
B — определение метрик, обучение, выбор порога и сравнение по типам.
Вместе — принятие allowlist/популяции и новая независимая проверка.
Пакет A — кандидат для экспериментов B, не разрешение на эксплуатацию.

## Статус Q1/A на 26.09.2026

[A подготовил и проверил полный пакет](ml-quality-improvement-a-review.md):
7 870 121 строка, 72 месяца и 71 признак. QA-гейт не изменил допуск
ни одного прежнего ключа. QA-сигналы редки, а базовые 51 поля в этой
популяции после наложения не изменились. B завершил ревью и контрольное
обучение; отрицательный результат описан ниже, целевые метрики не достигнуты.

После независимой сверки счётчиков R3/R4 A подтверждает ограничение B:
261 доступный validation-эпизод из 2 142 назначенных, верхняя граница
основного Recall **12,18%**. Q1 не изменяет допуск и не может достичь
Recall >0,5 ни выбором модели, ни порогом. Q1 — контроль влияния признаков.
Для достижения целей необходим Q2: сначала совместно определить и проверить
новый причинный допуск и надёжные метки; не тратить большой перебор моделей
на заведомо недостижимую цель в старой области.

Завершён [поэпизодный аудит A для входа Q2](ml-admission-episode-audit-a.md):
95 217 положительных часов, 9 280 train/validation-эпизодов, сохранённые
причины каждого отсева и механические сценарии без изменения допуска.
Снятие одного базового запрета даёт максимум 843 validation-эпизода,
что недостаточно для цели. Новый индекс и пригодность расширенной ветви
этой диагностикой не утверждены.

Предложена и технически проверена [разреженная причинная ветвь Q2/A](ml-sparse-admission-proposal-a.md).
На ограниченном M1 replay: 951 допустимый час против 111 из 3 360,
без изменения R6/target. B [принял кандидат для полного измерения](ml-q2-b-sparse-admission-review.md),
но не для обучения/эксплуатации. Это proof кандидата, не полная популяция или
измеренное улучшение Recall. A опубликовал [полный Q2-пакет](ml-sparse-population-a-review.md):
72 месяца, 106 454 425 решений, 86 049 885 разрешённых строк с 121 кандидатным
признаком. Фактически доступны 1 359 из 2 142 validation-эпизодов (предел
Recall 63,45%). Предварительные 1 263 относились к короткому сохранённому
контексту A3; все 96 добавленных эпизодов сверены отдельно, семидневное
требование сохранено. Финальная техническая проверка A завершена без расхождений, затем
нужны независимая приёмка ключей/меток/allowlist и сравнение моделей B.

B [завершил контрольное сравнение Q1](ml-q1-b-qa-ablation-review.md), коммит `849ff54`.
На прежней одинаковой области QA-признаки не улучшили модель; baseline
сохраняется. Новый полный Q2-допуск пока не принят, новые Precision/Recall
не вычислены. Нельзя переносить отрицательный контроль Q1 на новые часы без проверки.

## Дополнительная диагностика Q2/A на 27.09.2026

[Аудит исходных запретов качества](ml-q2-quality-blockers-a-review.md)
выполнен на всех 72 месячных M1-файлах и 95 217 назначенных положительных
часах. Все 406 недоступных температурных validation-эпизодов сосредоточены
на одном канале `228571`, перед каждым в прошлом окне присутствуют
одновременные «Норма»/«Неисправен». Кандидаты совместимых пар «число + текст»
выделены, но не утверждены; прежние допуск/история/метки не переписаны.
Это ретроспективная диагностика, не новый causal-индекс или прирост Recall.

Следующий основной шаг остаётся за B: приёмка полного Q2 и сравнение моделей.
Параллельно B проверяет температурные трассы/повторы по текущему определению
эпизода. A не снимает защиты автоматически; отдельную причинную версию
совместимости можно реализовать после совместного согласования точных правил.
