R6 технически закрыт. B независимо принял ограниченный исторический P1 и
[техническое восстановление A/B](ml-shadow-pilot-b-checkpoint-acceptance.md).
Живой P3 остаётся открытым: [контракт источника](ml-shadow-source-contract-draft.md)
и эксплуатационные условия не согласованы.

По поручению пользователя начинаем отдельный [эксперимент улучшения Q1](ml-quality-improvement-plan.md).
Задача A: полностью материализовать 20 QA-счётчиков и применить QA-коррекции
к 51 базовому признаку на прежних train/validation-ключах, проверить
происхождение и причины низкого охвата. Отчёт и пакет передать B для
принятия allowlist/QA-гейта и обучения. Популяцию не расширять автоматически;
открытый test, исключённый 2021 год и замороженный R6 не использовать для настройки.

Часть Q1/A выполнена: [отчёт и ограничения](ml-quality-improvement-a-review.md),
7 870 121 строка / 72 месяца / 71 признак. Следующий шаг — независимая
проверка пакета B и его эксперименты train/validation; общий Q1 пока не закрыт.
Получен протокол B `9913c64`; A принимает полный эпизодный Recall и
независимо подтвердил предел 261/2 142 = 12,18% на старом допуске.
Q2 — следующий необходимый совместный шаг для расширения причинной области,
не автоматическое разрешение всех `unknown`.

Завершён [воспроизводимый поэпизодный аудит](ml-admission-episode-audit-a.md)
на всех train/validation-месяцах, пакет готов к передаче B. Дальше A
проектирует кандидат разреженной причинной ветви; популяцию и метки
согласовать с B до нового индекса и обучения. Пока новый допуск не принят.

## Что изменилось

Обязательная цепочка «детекторы → псевдометки → CatBoost» отменяется для
основной supervised-ветки. Первая рекомендованная цель — будущее новое
зарегистрированное «Неисправен»; правила исследовательской версии R1 приняты.
Кластеризация и IF остаются дополнительными признаками, их пользу проверяем позже.

Операционное решение для исследовательской цели зафиксировано в
[контракте R1](ml-r1-operational-accepted.md); полнота журнала остаётся допущением.
Полный ingestion уже выполнен: 259 453 121 чистая запись в
output/milestone1/full_20260922/. Его не нужно повторять ради новой разметки.
Текущие незавершённые features/A2 сохранить и довести по новым требованиям.

## Первое задание — R1/A1

Сделать воспроизводимый аудит технического соответствия состояний:
тип/исходный текст → наборы-кандидаты, expected/observed alarm, статус, происхождение.
Исходный CSV не менять. Полные дубликаты можно убирать в производном справочнике;
противоречия не разрешать выбором первой строки, большинства или совпавшего alarm.
Канал не содержит state_set_id, поэтому даже один кандидат не доказывает связь.

Передать B state_mapping_audit.parquet, числа по типам/годам, неизвестные
и конфликтующие состояния, версии/хеши и маленькие тестовые примеры.
Начальные фактические числа уже есть в аудите; это не готовые метки.

Одновременно проверить причины 0 eligible в сохранённой A2-выборке:
13 680 unknown, 720 excluded. Отделить непригодность numeric baseline
от пригодности дискретной истории и будущей цели. Не разрешать все строки
простым снятием проверок и не исключать state-каналы только за отсутствие чисел.

на всей истории до временного split. Номер кластера не target.

Каждый результат: тесты, команда воспроизведения, размеры, распределения,
покрытие и ограничения. На R2 можешь работать параллельно с эпизодами B:
общий вход — правила и контракт R1, а не готовая модель.
