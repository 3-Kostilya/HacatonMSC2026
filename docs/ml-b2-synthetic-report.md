# B2 — синтетический стенд и независимые проверки признаков

Дата: 2026-09-22. Владелец — B. Базовая ветка перед работой:
`5a1077519315b8de8d801a16c677115ad44d11f9`.

**Статус B2:** генератор, раздельные tuning/holdout-наборы, manifests,
структурная проверка и причинные проверки 20 каналов реализованы. Подключение
полной схемы часовых признаков A и совместная ручная проверка 20 реальных
каналов выполняются после появления A2. 2021 год запрещён конфигурацией и
валидатором; попытка назначить синтетический сегмент на 2021 год отклоняется.

## Что добавлено

- `build_b2_suite()` расширяет прежние девять сценариев до 17, не меняя
  прежний девятисценарный путь benchmark.
- `b2_validation.py` проверяет содержимое, причинность и независимость suites.
- `build_b2_synthetic.py` одной командой создаёт tuning, закрытый holdout и
  отчёт проверки. Существующий каталог не перезаписывается.
- Каждый manifest хранит SHA-256 всего потока и каждого сценария,
  `background_id`, `parent_background_id`, source interval, source channel IDs,
  seed, точные параметры и фиксированные 20 каналов для проверки.

Новые случаи: `numeric_stuck`, сезонность и тяжёлые хвосты как контроли,
dropout с известной периодичностью, деградация связи, общий пробел выгрузки,
общая смена среды и mixed-канал с числовой и дискретной ветвями. Они дополняют
drift, variance, level shift, spike, частые/штатные переключения, одиночную
тревогу, неизвестную периодичность и общий сбой контекста.

Отсутствие сообщения представлено отсутствием строки. Нулевое значение для
dropout не создаётся. `stuck` продолжает выдавать сообщения с одним значением.
Общий пробел выгрузки и общая смена среды являются control, а не набором
локальных физических отказов. У mixed-канала сохраняются обе ветви.

## Независимость tuning и holdout

Наборы различаются интервалами, каналами, scenario/background IDs,
parent backgrounds, параметрами и содержимым. Все шесть cross-suite проверок
прошли. Общих каналов, фоновых реализаций и временных интервалов нет.
Holdout не является копией tuning с другим seed.

В каждом наборе 17 сценариев. Tuning содержит 2 821 событие, holdout — 4 218.
Для каждого сценария есть минимум семь дней чистого прошлого. Валидация
использует эталонные поля, но генератор и профили не читают вывод детекторов.

## Проверка 20 каналов

Выборка каналов детерминирована и включает доступные типы numeric, state,
mixed, контекст и наблюдаемость. Для каждого канала сравниваются:

1. observability, вычисленная только по префиксу до `t`;
2. observability из полного ряда при том же `t`;
3. персональный профиль из префикса;
4. профиль из полного ряда с тем же cutoff.

Во всех 20 случаях результаты пары совпали, а последняя точка профиля строго
раньше `t`. Это проверяет текущие общие контракты observability/profile.
Часовые признаки A2 (окна, квантили, наклоны и availability schema) пока не
существуют в этой ветке, поэтому их значения здесь не объявлены проверенными.

## Результат старого baseline

Для регрессии отдельно запущен прежний benchmark на исходных девяти сценариях:
все девять путей выполнены, шесть прошли ожидания. Drift и variance дали по два
candidate, level shift — семь. Episode recall = 1,0, precision = 0,385.
Это воспроизводимое обнаружение дробления эпизодов для A3/B3, а не причина
подбирать B2 holdout или менять truth. Расширенные восемь сценариев имеют
research/applicability-контракты и не передаются старому benchmark, который
не умеет оценивать stuck, качество связи и mixed-ветви.

## Воспроизведение

```powershell
.\.venv\Scripts\python.exe -X utf8 analysis/build_b2_synthetic.py --output output/b2-repeat
.\.venv\Scripts\python.exe -X utf8 -m unittest stage1.test_b2_simulation -v
```

Текущие локальные артефакты: `output/b2-20260922-v2/`. Для использования
берутся четыре файла events/truth и `b2-validation.json`. Каталог
`output/b2-20260922/` создан до добавления проверки 20 каналов и считается
промежуточным. Регрессионный девятисценарный результат находится в
`output/b2-legacy-20260922/`.

Артефакты output исключены из Git. В Git передаются генератор, конфигурация,
валидатор, тесты, команда воспроизведения и этот отчёт.

## Следующая точка объединения

После готовности A2 B запускает эти же сценарии через часовые признаки A,
сверяет вручную рассчитанные границы `(t-W,t]`, пустые окна, MAD=0 и изменение
частоты регистрации на тех же 20 каналах. Найденные расхождения оформляются
как воспроизводимые тесты владельцу A. До этого B может переходить к автономной
части B3: автомату эпизодов на фиксированных последовательностях scores.
