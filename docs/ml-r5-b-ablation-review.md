# R5/B — абляция причинных признаков отклонений

**Часть B завершена на train/validation.** Сравнение показывает пользу блока
кластеров с переходами как *кандидата* для R6, но не даёт основания заменить
принятое простое правило R4 или объявить окончательный порог. При
исследовательском ограничении не более 2 предупреждений без нового эпизода
на 1000 канал-дней кандидат обнаружил 96 из 261 эпизода с 229 лишними
предупреждениями; правило R4 — 78 с 177. При одинаковых 177 лишних
предупреждениях кандидат обнаружил 77. Реальный допустимый бюджет ещё не
утверждён, а пороги выбраны на validation.

## Одинаковая популяция и граница данных

Из A3 и согласованного индекса R3/B локально воспроизведены признаки R5/A
для 72 месяцев train и validation: 7 870 121 допустимый час. Закрытый test
не считывался для обучения, оценки и выбора. Ошибку памяти при соединении
широкого A3-файла с узким списком ключей устранили чтением только допущенных
ключей через DuckDB. Независимый аудит пакета завершился `passed`: хеши,
каждый ключ, тип и число строк сверены; target и split отсутствуют в
R5-признаках. IF покрывает 7 192 689 часов train+validation; это в точности
сумма приведённых A покрытий train и validation. Неиспользуемый год в
воспроизведение и обучение не попадал.

Обучающие модели получили **одни и те же 136 992 строки**, из них 6 871
положительная. Validation — **1 365 077 строк** одного периода, 1 943
положительных часа из 261 эпизода, 117 266 канал-дней. У всех вариантов
одни метка, временной split, 51 утверждённый признак baseline, настройки
CatBoost и правило отбора отрицательных train-часов. Меняется только
добавленный блок R5. Пропуск R5-признака кодируется для CatBoost, строка
остаётся в оценке. Необученные типы и разрывы истории не превращаются в
нулевую аномалию. Номера кластеров не используются как упорядоченные
признаки. Признаки A для train рассчитаны временным OOF; fit validation
заморожен до её начала.

## Сравнение на всей validation-популяции

Все числа предупреждений ниже учитывают подавление повторов на канале в
течение 24 часов. Для каждого метода порог выбран на validation при одном
исследовательском ограничении: не более 2 предупреждений без нового
эпизода на 1000 канал-дней. Часовой PR-AUC — дополнительная, не эпизодная
метрика. Порог прежнего CatBoost R4 включён в сетку явно.

| Вариант | Часовой PR-AUC | Найдено эпизодов / 261 | Лишних предупреждений |
|---|---:|---:|---:|
| Правило R4, отдельный baseline | 0,1941 | 78 | 177 |
| CatBoost, 51 признак R4 | 0,1194 | 77 | 234 |
| + оконные контрасты | 0,1239 | 69 | 234 |
| + IsolationForest | 0,1451 | 80 | 228 |
| + расстояния до кластеров | 0,1314 | 69 | 219 |
| + кластеры и переходы режимов | 0,1476 | **96** | 229 |
| + отдельный change point | 0,1111 | 58 | 224 |
| Все девять R5-признаков | **0,1551** | 84 | 227 |

Полный набор даёт лучший часовой PR-AUC среди CatBoost-вариантов, но
хуже блока кластеров с переходами по обнаруженным эпизодам. Оконные
контрасты и отдельный change point не показали самостоятельной пользы по
эпизодной метрике в этом эксперименте. Для кандидата с переходами порог
validation равен 0,9842694865; его нагрузка — 1,953 лишних предупреждения
на 1000 канал-дней. Это **кандидат**, не эксплуатационная настройка.

Если ограничить все методы ровно уровнем правила R4 (не более 177 лишних
предупреждений), блок кластеров с переходами на проверенной сетке порогов
даёт 77 обнаруженных эпизодов при 165 лишних. Правило остаётся 78/177.
Таким образом, прирост 96 против 78 использует свободную часть более
широкого исследовательского бюджета, а не доказывает превосходство при
неизменной фактической нагрузке.

## Покрытие, месяцы и типы

IF доступен для 123 466 из 136 992 выбранных train-строк; полный блок
кластеров с переходами — для 116 787. На validation кластеры покрывают
все 1 365 077 строк, а переходы и полный набор — 1 302 408 (95,4%).
На общей области полных R5-признаков остаются 1 783 положительных часа
из 195 эпизодов; **66 эпизодов не следует исключать** из основного
сравнения. В основном отчёте они сохранены, а метрики общей области
даны только как проверка чувствительности.

Месячный PR-AUC варианта с переходами выше R4 CatBoost в 9 из 12
validation-месяцев. Однако по отдельным предупреждениям картина неравномерна:
в январе–августе кандидат чаще находит дополнительные эпизоды, а в
последних месяцах есть потери относительно правила. Из 96 найденных
эпизодов 53 совпадают с правилом, 43 новые, 25 найденных правилом
пропущены кандидатом.

Из 118 эпизодов дымовых датчиков правило находит 33, кандидат — 30;
из 116 эпизодов «Состояния фазы» соответственно 40 и 62. У ИБП оба
находят 4 из 17. У остальных типов положительных эпизодов от 1 до 4,
поэтому типовые выводы для них ненадёжны. Часовой PR-AUC кандидата для
дымовых датчиков вырос с 0,212 до 0,295, но единый порог уменьшил
количество найденных дымовых эпизодов — ещё одна причина не внедрять его
без следующей проверки. Подробные помесячные и типовые счётчики лежат в
локальном `output/r5-b-alert-stability-20260925/report.json`.

## Решение B и воспроизведение

Для R6 сохраняем правило R4 как основной baseline и передаём вариант
**кластеры + переходы** как исследовательский кандидат. Полный набор не
выбираем автоматически по часовому PR-AUC. Перед окончательным выбором
нужны независимое подтверждение A для результатов B, утверждённый бюджет
предупреждений, проверка причинного batch/replay и ресурсов; затем следует
зафиксировать порог на validation и однократно проверить закрытый test.
Прогнозируется будущая **запись «Неисправен» в журнале** при условном
предположении о полноте архива, а не доказанная физическая поломка.

Локальные пакеты `output/r5-a-anomaly-features-20260925-b-trainval/`,
`output/r5-b-fixed-population-ablation-20260925/` и
`output/r5-b-alert-stability-20260925/` не входят в Git. Хеши манифестов
закреплены в `ml/r5_b_ablation_decision_v1.json`. Оригинальный полный ZIP
A локально не передавался; вместо него B пересчитал разрешённые 72 месяца
из тех же A3/R3-источников и проверил покрытие аудитом. Код сравнения
принимает и полный A-пакет, но строки закрытого test не открывает.

Из корня репозитория, с установленными зависимостями, повторный запуск в
**новые пустые папки**:

```powershell
.\.venv\Scripts\python.exe -B -m analysis.build_r5_a `
  --a3 output/r3-a-full-months-20260924 `
  --candidates output/r3-b-conditional-discrete-20260925 `
  --output output/r5-a-trainval-replay --score-end 2025-12
.\.venv\Scripts\python.exe -B -m analysis.audit_r5_a `
  --a3 output/r3-a-full-months-20260924 `
  --candidates output/r3-b-conditional-discrete-20260925 `
  --output output/r5-a-trainval-replay
.\.venv\Scripts\python.exe -B -m analysis.run_r5_b_ablation `
  --a3-dir output/r3-a-full-months-20260924 `
  --b3-dir output/r3-b-full-months-20260925-v2 `
  --index-dir output/r3-b-conditional-discrete-20260925 `
  --r5-dir output/r5-a-trainval-replay `
  --r4-dir output/r4-b-conditional-discrete-baselines-20260925-v5 `
  --r4-audit-dir output/r4-b-validation-audit-20260925 `
  --r4-budget-dir output/r4-b-alert-budget-comparison-20260925-v2 `
  --output-dir output/r5-b-ablation-replay
.\.venv\Scripts\python.exe -B -m analysis.summarize_r5_b_alert_stability `
  --r5-dir output/r5-b-ablation-replay `
  --r4-audit-dir output/r4-b-validation-audit-20260925 `
  --output-dir output/r5-b-stability-replay
```
