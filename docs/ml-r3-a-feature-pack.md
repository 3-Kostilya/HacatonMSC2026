# R3 A — причинный пакет признаков

## Что передаётся B

`analysis/build_r3_a_feature_pack.py` публикует неизменяемый пакет на основе
проверенных A2 и R2 с каталогом B2. Версия пакета — `r3-a-feature-pack-v1`.
В `manifest.json` записаны SHA-256 A2, R2, M1 и каталога B2, версия правил,
границы каждой месячной части, количество строк и контрольные суммы файлов.
Источник с другим M1, неполным/подменённым R2, неравными ключами или без
проверенного каталога B2 отклоняется до публикации.

В каждой `year=YYYY/month=MM/` находятся два файла с одинаковыми ключами
`channel_id, prediction_time`:

- `features.parquet` — ключи и только прошлые значения признаков;
- `row_status.parquet` — причины отсутствия, статусы числовой/дискретной ветви,
  статус истории эпизодов и время окончания базовой подгонки.

`model_feature_allowlist.json` перечисляет 111 разрешённых признаков с типами.
Ключи, статусы, provenance, ID исходных событий и эпизодов, будущие сообщения,
`target`, причина исхода, `split` и решение о пригодности к обучению не входят
в allowlist. B должен присоединить свою цель и временные части только по двум
ключам, а при обучении выбирать столбцы строго из allowlist. Прошлые сообщения
«Неисправен» и «Норма» разрешены; прогнозная цель относится к **(t, t+24h]**.
Прошлые завершённые эпизоды учитываются только если их восстановление известно
к моменту `t` и не переходит через исключённый 2021 год.

## Текущий реальный проверочный выпуск

Путь: `output/r3-a-feature-pack-real20-june2025-b2-verified/` (игнорируется Git).
Исходники — A2 20 каналов за июнь 2025 и R2 с B2, совпадающим по M1.
Получено 14 400 часовых строк, один месячный раздел, 111 признаков.
Проверка статусов: A2 — 13 680 `unknown` и 720 `excluded`; числовая ветвь —
1 205 `eligible`; дискретная — 2 134 `eligible`. Пакет имеет
`purpose=qa_only`, `not_training_ready=true`: каналы для A2 выбирались с
учётом наличия записей в проверяемом периоде. Эти строки **нельзя** выдавать
за честные train/validation/test или использовать для оценки модели.

Команда повторения (из корня репозитория):

```powershell
.venv\Scripts\python.exe analysis/build_r3_a_feature_pack.py `
  --a2-dir output/milestone2/a2-real20-june2025 `
  --r2-dir output/r2-a-state-history-real20-june2025-with-b2 `
  --output output/r3-a-feature-pack-real20-june2025-b2-rebuild
```

Публикация не перезаписывает существующий каталог; при повторе нужен новый
`--output`. Каталоги `output/` надо передавать отдельно от Git, если B хочет
читать сами Parquet. Код, тесты и этот контракт передаются через ветку `ML`.

## Проверки и границы приёмки

- Проверяются SHA-256 источников, версии, M1/B2 lineage, точное совпадение
  всех ключей A2/R2, число строк, часовая сетка и предел базовой подгонки
  до 168-часового окна с embargo.
- Тест с добавлением будущего сообщения показывает, что уже рассчитанные
  признаки в `t` не меняются. Тесты проверяют границу месяцев, allowlist и
  отклонение неверного provenance. Текущий A2/R2 расчёт уже отдельно проверен
  против B2-трасс в `docs/ml-r2-a-state-features.md`.
- A3 сейчас даёт проверенный формат и QA-выпуск, **не массовую прогнозную
  выборку**. Для полной приёмки R3 B должен опубликовать `0/1/unknown/excluded`,
  temporal split/purge и отчёт по классам/каналам/эпизодам. Затем нужна
  отдельная причинная массовая сборка по согласованной популяции каналов;
  20-канальную A2 QA-выборку для неё повторно использовать нельзя.
