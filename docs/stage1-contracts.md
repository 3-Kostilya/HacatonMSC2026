# Контракты данных первого этапа

Версия: `stage1-v1`. Время хранится в локальном времени журнала без искусственно
назначенного часового пояса. Исходное текстовое значение никогда не заменяется числом:
для смешанных каналов сохраняются оба представления.

## Нормализованное событие

Обязательные поля: `channel_id`, `timestamp`, `raw_value`, `alarm`, `sensor_type`,
`source`. Дополнительные: исходный `event_id`, подтверждённый `object_id`, разобранное
`numeric_value` и список `quality_flags`.

`object_id` остаётся пустым, если надёжной связи нет. Технический тег не используется
для её восстановления. Конфликтующие значения в одну секунду не упорядочиваются
произвольно: они сохраняются как отдельные наблюдения и получают флаг качества на
следующем шаге подготовки.

## Карточка результата

Один и тот же формат представляет три исхода:

- `candidate` — есть устойчивые основания подозревать аномальный эпизод;
- `no_candidate` — данных достаточно, но условия детектора не выполнены;
- `unknown` — сделать вывод мешает наблюдаемость или неизвестный смысл данных.

Карточка содержит канал и тип, группу, тип наблюдаемой аномалии, гипотезу причины,
время предполагаемого начала и подтверждения, необязательное время окончания,
основания, качество наблюдений, происхождение данных и версию правил. Численный
`score`, если он есть, лежит в `[0, 1]`, но не называется вероятностью физической
поломки.

Для `candidate` обязателен хотя бы один понятный пункт `evidence`. Для `unknown`
обязательна причина в `observation_quality`. `confirmed_at` не может быть раньше
`start_at`: это разделяет ретроспективное начало и момент, когда причинный детектор
получил достаточно данных.

Исполняемая спецификация находится в `stage1/contracts.py`; базовые инварианты
проверяются `python -X utf8 -m unittest stage1.test_contracts -v`.
