# Базовые детекторы и сборка эпизодов — День 3

Статус: реализовано как независимое ядро над `NormalizedEvent` в памяти. Пороговые
значения пока являются конфигурируемыми гипотезами и должны калиброваться только
после разметки и проверки на временном holdout.

## Общие гарантии

- результат любого правила — контракт `Episode` с одним из исходов `candidate`,
  `no_candidate`, `unknown`;
- история одного вызова обязана относиться к одному каналу и типу датчика;
- базовый участок строго предшествует проверяемому участку, его последняя дата
  записана в `metadata.baseline_end_at`;
- `start_at` — первое событие устойчивой последовательности, `confirmed_at` —
  событие, на котором накопилось требуемое число подтверждений;
- кандидат всегда содержит проверяемый `evidence`, а `unknown` — причину в
  `observation_quality`;
- одиночный числовой выброс, одно редкое состояние и редкие одинаковые сообщения,
  разнесённые дальше окна, не создают кандидата;
- флаги нормализатора `channel_time_conflict`, `invalid_timestamp` и для чисел
  `nonfinite_numeric` безопасно переводят оценку в `unknown`.

## Числовое правило

`detect_numeric_level_shift` сравнивает только проверяемый хвост с медианой более
раннего базового участка. Масштаб — MAD. Кандидат возникает лишь после
`min_sustained` последовательных отклонений одного знака за порог
`mad_multiplier * MAD`.

При нулевом MAD деление не выполняется: используется явно настроенный
`zero_mad_absolute_delta`, и этот выбор отражается в evidence. Нехватка
`baseline_size + min_sustained` числовых точек даёт `unknown`, а не норму.

## Дискретные правила

`detect_discrete_pattern` проверяет два объяснимых сценария:

1. `repeated_state_burst` — не менее `repeated_state_count` одинаковых сообщений
   внутри `repeated_state_window`, если такой темп отсутствовал в baseline либо
   ускорился не менее чем в `repeat_acceleration_factor` раз;
2. `rapid_switching` — не менее `transition_count` реальных переходов внутри
   `transition_window`.

Словарь состояний можно зафиксировать через `known_states`. Значение вне словаря
даёт `unknown`: ядро не придумывает физический смысл неизвестного кода.
После `transition_window` без нового перехода `rapid_switching` закрывается; новый
всплеск после восстановления создаёт отдельный Episode.

## Контекст

`detect_context_coincidence` не делает межканальный вывод без подтверждённой связи.
В текущем контракте минимальным доказательством служит одинаковый непустой
`object_id`; при его отсутствии результат всегда `unknown`. Даже при связи нужны
как минимум две причинно допустимые совместности: контекстное событие должно
произойти не позже целевого. Совместность остаётся гипотезой общей причины, а не
доказательством отказа каждого датчика.

## Сборка эпизодов

`consolidate_episodes` выполняет три операции:

- объединяет близкие срабатывания с полностью одинаковым ключом «канал, тип
  датчика, тип аномалии, гипотеза причины»;
- закрывает эпизод датой подтверждённого восстановления из
  `recovery_by_channel`;
- подавляет повторное срабатывание того же ключа в настраиваемом окне после
  восстановления.

Разные каналы, типы аномалий и гипотезы причин не объединяются. Результаты
`unknown` и `no_candidate` сохраняются без потери.
Если последняя объединяемая часть остаётся активной, общий эпизод также остаётся
открытым: более раннее восстановление не переносится на новое событие.

состояние, реальный конфликт нормализатора, evidence, разные `start_at` и
`confirmed_at`, защищённый контекст, merge, recovery и suppression.
