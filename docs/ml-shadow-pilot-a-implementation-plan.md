# Теневой пилот после R6 — технический протокол A

Дата: 26.09.2026. R6 технически закрыт; этот план его не переоткрывает.
Дополняет общий `ml-shadow-pilot-plan.md`, подготовленный B.
Статус: техническая часть A разрешена; совместные критерии и эксплуатация
ожидают ревью B и решения заказчика. Работаем в единственной ветке `ML`.

## Цель и ограничения

Проверить путь «уже поступившие события → причинный допуск → четыре входа
замороженного правила → исследовательское предупреждение». Не читать target,
пригодность будущей метки, temporal split, индекс R3 и полный каталог B2
внутри inference. Отсутствие прогноза не означает нулевой риск.

Формула R6, порог 7,1 и cooldown 24 часа неизменны. Цель остаётся будущей
записью «Неисправен» в журнале, а не подтверждённой физической поломкой.
Предупреждения только сохраняются; никаких управляющих команд, уведомлений
оператору или автоматического ремонта этот код не отправляет.

Текущие файлы позволяют сделать **историческую имитацию потока**, не настоящий
проспективный пилот. Новый независимый результат качества требует новых событий
и последующей разметки. Уже открытый test не используется для настройки.
Охват R6 9,38% не переносится на новую популяцию.

## Этапы и владельцы

| Этап | Владелец | Результат и условие перехода |
|---|---|---|
| P0 Протокол | A, затем B | Этот план и версионированный контракт; B ревьюит смысл допуска |
| P1 Причинный расчёт | A | Явные причины отсутствия прогноза, поток событий, восстановление завершённых эпизодов только по уже известным переходам, тесты и ограниченный replay |
| P2 Критерии и реакция | B | Охват и нагрузка по типам, критерии задержки/памяти, обработка повторов, неизвестных часов и действий оператора; утверждение бюджета заказчиком |
| P3 Совместная проверка | A + B | Согласованный допуск, сверка четырёх входов, replay/ресурсы/ошибки и воспроизводимость; только после этого разрешение на теневой запуск новых событий |
| P4 Новая оценка | B + A | Новые события, созревшая разметка и независимая оценка; улучшения без настройки на открытом test R6 |

## Технические критерии P1, фиксируемые до replay

- Все выбранные каналы и каждый запрошенный час учитываются, даже без «Норма».
  Каналы выбираются по информации **до начала** replay, без будущих событий.
- В прогноз в `t` входят только целиком полученные группы событий с временем
  `<=t`. Сначала закрывается канал-секунда, затем разрешается прогноз.
  Источник обязан обеспечить этот watermark; поздние события после прогноза
  отвергаются, а не молча меняют опубликованный результат.
- Допуск сохраняет прошлые требования дискретной ветви A2/R2: история,
  дневной baseline с embargo, текстовые наблюдения за 24 часа и проверки
  качества. Дополнительно нужна недавняя явная «Норма», отсутствие активного
  зарегистрированного эпизода и неопределённого прошлого состояния.
- Baseline каждого дня заканчивается за 168+24 часа до его начала;
  глубина baseline — 28 дней. Хранится ограниченная история 37 дней,
  краткая накопленная метаинформация и незавершённое состояние канала.
- Счётчик завершённых эпизодов обновляется только при поступившей «Норма»;
  бесспорность определяется на этом префиксе по принятым правилам B2.
  Полная прошлая текстовая история нужна для восстановления состояния;
  её нельзя безусловно заменить коротким прогревом в 37 дней.
- Разрыв 2021 года сбрасывает историю. CSV-пример и неверные годовые источники
  не входят в расчёт. Непрерывность работы канала по-прежнему `unknown`.
- Изменение/добавление будущих событий не меняет прежние строки; пакетный
  replay и последовательный префикс совпадают. Допустимые расхождения — **0**.
- У каждой строки есть статус, причины, версии, score либо null;
  неизвестные часы не получают score=0. Повторы подавляются причинно.
- Отчёт содержит охват/причины и предупреждения по типам, время и память.
  Порогов успешности по качеству/охвату/SLA пока нет: их нельзя выдать за
  согласованные с заказчиком. Предел 2/1000 канал-дней не критерий приёмки.

## Первый ограниченный replay A

Фиксируем технический интервал `2025-12-01 00:00` — `2025-12-08 00:00`,
не более 20 каналов: по одному детерминированному каналу на тип, выбранному
по прошлым наблюдениям. Это намеренно небольшой диагностический срез,
не оценка всего M1 и не сравнение качества моделей.

Источники — существующий M1, локальные месячные Parquet. Сырьё повторно
не загружается. Графики обслуживания и новые QA-счётчики не добавляются
в замороженное правило. Сторонние пакеты A3/B3/R3/B2 для inference не нужны.

P1 не утверждает историческую актуальность справочника каналов, задержку
доставки реального журнала, полноту наблюдений, восстановление после падения
процесса или работоспособность будущего промышленного источника. Эти вопросы
явно остаются для совместного P3 и настоящего пилота.
