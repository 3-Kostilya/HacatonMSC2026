# R4/A — воспроизведение validation и проверка ресурсов

**Решение A:** техническая часть R4/A принята для условного прогноза будущей
зарегистрированной записи «Неисправен». Предлагаю закрыть совместный R4 после
ознакомления B с этой сверкой. Это не утверждение о физической поломке,
не финальный эксплуатационный порог и не результат закрытого test.

## Входы и объём

Ветка `ML` содержит исправление переносов LF/CRLF из коммита `1ab27f9`.
Перенесённые из пакета B локальные каталоги R3 и R4 лежат в `output/`.
SHA-256 манифестов моделей, validation-аудита, кривых порогов, устойчивости
и 50 трасс совпали с `ml/r4_b_baseline_decision_v1.json`. Проверка входов
`verify_inputs` прошла для всех 78 месячных частей и 51 признака;
манифесты A3/B3 совпали с принятым контрактом R3.

Из сохранённых моделей повторно рассчитаны все 12 месяцев validation 2025:
**1 365 077** часовых точек и **261** положительный эпизод. Использованы
только сохранённые причинные признаки A3, индекс допуска R3 и модели B;
test-строки и метки не использовались для прогноза, подбора или оценки.
Общая проверка целостности хешировала исходные файлы всех частей и
проверяла их схемы. Результат второго запуска находится в
`output/r4-a-validation-resource-check-20260925/`, SHA-256 его манифеста —
`bf1149900e74d6bb91404949b008e0c8ad27725cb742975386136f916f61b762`.

Аудитор `analysis/audit_r4_a_batch_replay.py` сопоставил каждую часовую
точку с пакетом B по `(channel_id, prediction_time)`, а не по порядку строк:
все ключи, цели и остальные поля совпали. Порядок строк различается во
всех 12 месячных файлах, поэтому побайтовые SHA-256 Parquet ожидаемо
разные. Баллы правила и CatBoost совпали точно; наибольшее расхождение
Logistic Regression — `5,97 × 10⁻¹⁶`, ниже допуска `10⁻¹²`. Три таблицы
предупреждений также совпали по ключам, исходам и баллам в том же допуске.
Глобальные метрики и происхождение положительных эпизодов совпали точно;
три помесячных PR-AUC логистической модели отличаются лишь последними
десятичными разрядами из-за округления. SHA-256 отчёта A:
`3f1190ff11ae49834d0b63f92bb70efc42840a1a52f7e666f725b48904e95f32`.

Отдельно пересчитан кандидат B при пороге **7,1** и подавлении повторов
на 24 часа: **78** найденных эпизодов из 261, **177** лишних предупреждений,
то есть 1,509 на 1000 канал-дней. Это точно совпало с решением B и
кривой при исследовательском бюджете не более 2 лишних предупреждений
на 1000 канал-дней. Бюджет не утверждён продуктом; итоговый порог
по-прежнему `null`.

## Ресурсы и воспроизведение

На этой машине полный повторный расчёт validation занял **30,77 с**;
пиковая суммарная рабочая память процессов Python при опросе каждые
100 мс — **1,89 GiB**. До запуска других процессов Python не было.
Это измерение расчёта из готовых A3/R3-таблиц, не полного построения
признаков из 259 млн исходных сообщений. Повторный запуск завершился
без ошибок и прошёл ту же поключевую сверку.

```powershell
.\.venv\Scripts\python.exe -B analysis/audit_r4_b_validation.py `
  --a3-dir output/r3-a-full-months-20260924 `
  --b3-dir output/r3-b-full-months-20260925-v2 `
  --index-dir output/r3-b-conditional-discrete-20260925 `
  --b2-dir output/r2-b-registered-episodes-full-r1v2 `
  --model-dir output/r4-b-conditional-discrete-baselines-20260925-v5 `
  --output-dir output/r4-a-validation-replay-new
.\.venv\Scripts\python.exe -B analysis/audit_r4_a_batch_replay.py `
  --b-dir output/r4-b-validation-audit-20260925 `
  --a-dir output/r4-a-validation-replay-new `
  --budget-dir output/r4-b-alert-budget-comparison-20260925-v2 `
  --output-dir output/r4-a-batch-replay-review-new
```

Создавать новые имена выходных каталогов: завершённые пакеты не перезаписываются.
Пакет B `output/` остаётся вне Git, поэтому другому участнику он нужен
отдельно. У A нет очищенного M1 по пути из инструкции B; 50 исходных
трасс B подтверждены совпадением хеша переданного пакета, но A их
самостоятельно из M1 не пересчитывал. Сквозное равенство train/inference
из сырых событий относится к R6.
