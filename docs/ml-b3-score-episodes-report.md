# B3 — автомат эпизодов на последовательностях scores

Дата: 2026-09-22. Владелец — B. Вход A3 пока недоступен, поэтому выполнена
автономная часть B3 на фиксированных последовательностях scores.

## Реализованный контракт

`stage1/score_episodes.py` принимает причинно упорядоченные оценки и строит
эпизоды отдельно для `(channel, sensor type/group, anomaly type, cause)`.
Поддерживаются статусы `eligible`, `unknown`, `excluded`; недоступная оценка
обязана быть `null` с причиной и не превращается в нулевой риск.

Настройки по умолчанию для fixture:

- вход при score ≥ 0,8 на трёх последовательных наблюдениях;
- восстановление при score ≤ 0,4 на трёх последовательных наблюдениях;
- область между порогами удерживает текущее состояние;
- разрыв более двух часов сбрасывает неподтверждённую серию;
- `start_at` — первая точка подтверждающей серии;
- `confirmed_at` — точка, на которой набрано подтверждение;
- `end_at` — точка подтверждения устойчивого восстановления;
- первая низкая точка восстановления сохраняется отдельно в metadata.

Эти числа проверяют автомат и не объявлены рабочими порогами. Порог и частота
A3 должны быть зафиксированы на tuning до закрытого теста.

В episode сохраняются peak score/time, методы и версии, число наблюдений,
evidence, причины unknown внутри эпизода и детерминированный ID. Разные виды
аномалий не объединяются. Повторные высокие оценки активного воздействия не
создают новые эпизоды.

## Восстановление, cooldown и уведомления

Эпизоды и уведомления имеют разные структуры. Уведомление создаётся после
подтверждения эпизода; повторная передача того же episode ID подавляется.
После подтверждённого восстановления новая серия получает новый episode ID
и уведомляется даже внутри большого cooldown. Так cooldown не скрывает новое
воздействие и не влияет на каталог эпизодов.

Unknown внутри активного эпизода сбрасывает серию восстановления, сохраняет
причину качества и оставляет эпизод открытым. Одна нормальная точка также не
закрывает эпизод.

## Оценка вида аномалии

`evaluate_anomaly_kinds()` сопоставляет воздействия и episodes один к одному,
после чего отдельно возвращает:

- факт обнаружения воздействия (`impact_recall`);
- правильность вида среди обнаруженных (`kind_accuracy_on_detected`);
- лишние предупреждения.

Поэтому обнаружение variance-воздействия эпизодом `level_shift` считается
обнаруженным воздействием, но ошибкой вида. Метрика вида не подменяет episode
Precision/Recall из общего evaluator.

## Исполняемая приёмка

`analysis/run_b3_score_sequences.py` проверяет восемь условий:

1. устойчивое воздействие даёт один эпизод;
2. начало и подтверждение различаются;
3. будущие точки не меняют ID, начало и подтверждение прошлого эпизода;
4. после восстановления формируются два эпизода;
5. cooldown не скрывает второй эпизод;
6. unknown-gap не закрывает активный эпизод;
7. обнаружение и вид оцениваются отдельно;
8. 2021 год отсутствует.

Все условия прошли. Результат находится в
`output/b3-20260922/b3-validation.json` и исключён из Git.

## Подключение A3

`score_observation_from_record()` принимает M0 envelope `anomaly_scores`:
`channel_id`, `as_of`, `method`, `method_version`, `score`, `score_status`,
`score_reasons`, `evidence`. Для полноценной проверки вида A должен добавить
семантические поля `anomaly_type`, `sensor_type`, `sensor_group` и при наличии
`cause_hypothesis`, `object_id`. Если `anomaly_type` отсутствует, временный
адаптер использует имя метода; для финальной оценки вида этого недостаточно.

После A3 остаётся прогнать неизменный автомат на его scores, проверить cadence,
подобрать thresholds только на tuning и выполнить episode/kind-оценку. Код B3
не должен подстраиваться по закрытому holdout.

## Воспроизведение

```powershell
.\.venv\Scripts\python.exe -X utf8 analysis/run_b3_score_sequences.py --output output/b3-repeat/b3-validation.json
.\.venv\Scripts\python.exe -X utf8 -m unittest stage1.test_score_episodes -v
```

Старый `consolidate_episodes()` сохранён для готовых детекторных Episode.
Новый автомат применяется к временным последовательностям scores и не меняет
контракт существующего pipeline до передачи A3.
